# Моя история

Личный дневник поездок: маршрут, контрольные точки, фото, видео и голосовые заметки.
Один код для iPhone, Android, ПК и браузера (Next.js + PWA).

## Что уже работает

- **Поездки**: создание, обложка, описание, дата и время.
- **Режим «История»**: извилистый вертикальный путь, построенный из порядка точек
  (`lib/storyLayout.ts`). Раскладка детерминирована (seed = id поездки + id точки)
  и работает для любого количества точек.
- **Контрольные точки**: форма (круг, квадрат, треугольник, ромб, звезда, шестиугольник),
  любой цвет, 4 размера, важность, значок, фото-превью внутри значка, порядок,
  редактирование и удаление.
- **Большая локация**: отдельная страница с обложкой, галереей, видео, голосовыми
  заметками, временем пребывания и мини-событиями.
- **Маршрут задаётся вручную**: пользователь сам добавляет точки по порядку
  (дом → станция → электричка → … → место назначения). Реальные карты не подключены.
- **Медиа**: фото сжимаются и хранятся в IndexedDB (не в localStorage), у каждого файла
  свой `media_id`.
- **Способ передвижения** на каждом участке (пешком, электричка, метро, автобус, такси…):
  свой стиль линии и значок посередине участка (`lib/travel.ts`).
- **Аккаунт** (Supabase, вход по коду из письма) и перенос поездок с устройства в облако.
- **PWA**: manifest, иконки, Apple touch icon, standalone, safe areas, service worker.

## Архитектура данных

```
Trip ── checkpoints[] (порядок массива = порядок пути)
     │      └─ location {lat, lon, label}, style {shape, color, size}, mediaIds[], place?
     └─ (route — зарезервировано, сейчас не используется)
```

- Модель (`lib/types.ts`) не зависит от картографических сервисов: у точек хранится
  своё название места (и при желании координаты), так что карту можно подключить позже.
- Медиа адресуются внутренним `media_id`. Где лежит файл, определяет отдельная
  таблица `media_storage` (provider + location), поэтому перенос хранилища
  (Supabase → Google Drive, старый Drive → новый) не меняет записи дневника.
- Хранилище поездок (`lib/repo.ts`): локально (IndexedDB) или Supabase после входа.

## Переменные окружения (Vercel → Settings → Environment Variables)

| Переменная | Где используется | Обязательна |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | аккаунт и синхронизация | позже |

Для запуска сейчас переменные не нужны. Реальные ключи в репозиторий не коммитятся (`.env*` в `.gitignore`).

## Аккаунт и синхронизация (Supabase)

Без Supabase всё хранится на устройстве. Чтобы история была одинаковой на всех устройствах:

1. supabase.com → New project.
2. SQL Editor → вставить `supabase/schema.sql` → Run (создаст таблицы, защиту строк и bucket `media`).
3. Authentication → Email: включить. В шаблоне письма «Magic Link» добавить код `{{ .Token }}`,
   чтобы входить по коду (нужно для PWA на iPhone).
4. Authentication → URL Configuration → Site URL = адрес сайта на Vercel.
5. Project Settings → API: скопировать `Project URL` и `anon public` ключ в Vercel как
   `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` → Redeploy.
6. В приложении: кнопка «Я» → вход по email → «Перенести в аккаунт».

## Деплой

1. vercel.com → Add New → Project → импортировать `nemec8912-eng/My-history`.
2. Framework: Next.js (определится сам), ветка Production: `main`.
3. Deploy (переменные окружения пока не нужны).
4. Каждый push в `main` обновляет один и тот же Production URL.

Каждый push проверяется GitHub Actions (`.github/workflows/ci.yml`):
`npm install` → `tsc --noEmit` → `npm run build`.
